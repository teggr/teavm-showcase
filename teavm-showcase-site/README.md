# TeaVM Showcase website

An editorial companion site generated by the **Electrostatic Maven plugin 0.0.4**, with the four existing TeaVM applications published under one origin.

## Build and preview

Use **JDK 21 or newer** (required by Electrostatic), Maven 3.9+, and run from the repository root:

```sh
mvn clean verify
```

The deployable directory is `teavm-showcase-site/target/generated-site/`. To preview the complete assembled site:

```sh
jwebserver -b 127.0.0.1 -p 8097 -d teavm-showcase-site/target
```

Open <http://127.0.0.1:8097/generated-site/>. The extra path deliberately exercises project-page-relative URLs. On Windows, use backslashes in filesystem paths.

After an initial reactor build, presentation-only changes can be rebuilt with:

```sh
mvn -pl teavm-showcase-site package
```

Build from the reactor root whenever an application changes. The assembly fails explicitly if an app's TeaVM output is missing; a site-only build does not rebuild the four applications.

## How it is assembled

`src/main/resources/site/site-config.xml` configures Electrostatic. The custom homepage and its assets live under `_static/`, using Electrostatic's supported static-file publishing mechanism rather than a built-in blog layout. There are no posts and no competing generated index page.

Maven copies the site source into `target/classes/site/` and creates the empty collections required by Electrostatic's default theme. The plugin generates the site during `prepare-package`. `AssembleSite` then copies the compiled browser apps into:

| Experiment | Published route | Original module |
| --- | --- | --- |
| Play | `examples/play/` | `teavm-showcase-platform-game` |
| Create | `examples/create/` | `teavm-showcase-drawing-app` |
| Connect | `examples/connect/` | `teavm-showcase-currency-converter` |
| Learn | `examples/learn/` | `teavm-showcase-number-guessing` |

Only the **published copies** receive the exhibition navigation and shared `assets/demo-theme.css`. The standalone HTML and application workflows are preserved. The drawing app's colour swatches and Java drawing colours use the exhibition palette consistently.

GitHub Pages cannot host Spring Boot. The published currency page explicitly opts into `data-static-fixtures="true"`. Its TeaVM Java client calls the **same `ConversionService` and `ExchangeRates` used by the Spring API**, including decimal rounding and the seven illustrative history points. It makes no API request and labels its output as static demo fixtures, not market data. Without that attribute, the original client still posts to `/api/conversions`.

## GitHub Pages

`.github/workflows/pages.yml` runs `mvn clean verify` for pull requests and pushes to `main`. Pull requests build but **never deploy**. After the source branch is merged into `main`, the workflow uploads the assembled directory and publishes it using the official GitHub Pages actions.

In the repository's **Settings > Pages**, select **GitHub Actions** as the build source. The intended public URL is <https://teggr.github.io/teavm-showcase/>. All application and asset URLs are relative, so the repository subpath is preserved. A manual workflow dispatch on `main` can also publish; dispatches on feature branches do not deploy.

No Node.js build, API hosting, external font service, or Java runtime is needed by visitors.

## Browser screenshots and functional QA

The optional QA tooling uses **Java with JBang and Playwright**; it is not part of the site build. It uses installed Microsoft Edge on Windows or Playwright's Chromium elsewhere. JBang resolves the pinned Playwright dependency on first use.

With the preview server running, capture screenshots into a directory outside the repository:

```sh
jbang teavm-showcase-site/tools/BrowserQa.java http://127.0.0.1:8097/generated-site PATH_TO_SCREENSHOTS
```

Pass `teavm-showcase-site/target/generated-site/assets` as a third argument to regenerate the four real-application preview PNGs. Copy those four PNGs into `src/main/resources/site/_static/assets/`, rebuild the site, and run QA again without that argument to verify the exact deployable artifact.

The script exercises platform input/restart, drawing and recolouring, all 16 currency pairs with numeric rate assertions, amount validation, number-game win/reset, navigation targets, and desktop/tablet/mobile layouts. It rejects browser errors, failed resource requests, API requests from the static app, horizontal overflow, incorrect first-screen geometry, and missing reduced-motion support.

The design reference is **1672 x 941**. The target header is about 100 px high, the posters begin around y=407, and the black feature strip begins around y=840. Iterative screenshot comparisons corrected an initially over-tall poster row, footer clipping, angular collage shapes, mountain crop contamination, and tablet overlaps. Final desktop, 1024 px, 820 px, 390 px and individual mobile-app screenshots are captured by the script.

Intentional differences from the supplied image: previews show the **actual repository applications** (a geometric platformer, shape editor and a 1-to-10 number game), not the reference's invented pixel-art game, freehand painter or 1-to-100 interface. The actual apps use the supplied light paper design system rather than dark screenshot mockups. Cloud shapes, torn edges, doodles and lettering are implemented as lightweight SVG/CSS and local typography rather than exact raster copies.

## Asset provenance

- `portrait.png` and `mountains.png` are isolated cutouts from the reference artwork supplied for this project. The full reference is not used as the page background or checked into the repository. `tools/PrepareArtwork.java` reproduces the extraction when given the original reference PNG and the assets directory.
- `play.png`, `create.png`, `connect.png` and `learn.png` are browser screenshots of this repository's running Java applications, including real interactions.
- Inter Latin variable font is bundled locally from Fontsource's Inter distribution; its SIL Open Font License is included as `assets/INTER-LICENSE.txt`.
- The paper silhouettes, grain, favicon and line icons are local SVG assets. The GitHub mark identifies links to GitHub.
